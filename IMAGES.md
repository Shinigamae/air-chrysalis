# Image replacement guide

The site has very little local imagery. Builds, games, books and album art all
comes with its feed and is hotlinked, so what is actually committed here is
four homepage cards, the client art on `/workshop`, and the brand mark.

**Local art lives in `src/assets/`, not `public/`.** That is the whole
difference between the two directories: `public/` is copied to the build byte
for byte, while anything imported from `src/assets/` goes through
`astro:assets` — resized to the widths the page actually paints, re-encoded to
AVIF and WebP, and served as a `srcset`. Only `favicon.svg` still needs a
fixed URL, so it is the only thing left in `public/`.

To swap a photo, overwrite the file at the same path with the same filename.
Nothing in the code changes and the next build re-optimises it.

Regenerate the placeholders at any time (they are deterministic):

```sh
npm run placeholders            # only writes files that do not exist
npm run placeholders -- --force # overwrite, including real photos
```

**It will not overwrite an existing file without `--force`.** It used to, and
one stray run painted labelled boxes over all four home cards. Almost every
path it knows about now holds a real photo, so `--force` is close to a
destructive flag — it is for regenerating the three slots below that are still
placeholders, and it cannot tell them apart from the rest. Without it the
script prints `exists, kept` and moves on.

It launches a headless browser to render them, so there is no image library in
`package.json` for that. Set `CHROME_PATH` if it cannot find Chrome or Edge.

---

## Keeping the same filename but a different format

Where to edit if a file's extension changes:

| Kind | File to edit | Field |
| --- | --- | --- |
| Home cards | `src/config/home.ts` | the four `import`s at the top |
| Builds | `src/content/builds/<slug>.json` | `hero`, `gallery[]` |
| Games | `src/content/games/games.json` | `screenshots[]` |
| Books | `src/content/books/books.json` | `cover` |

Home cards are imports rather than paths, so a wrong filename is a build
error rather than a silent 404. The remote ones are strings in content JSON,
written as `/images/...` or as a full URL; `withBase()` adds the base path at
render time, so **do not put the base in the content files**.

Simplest path either way: **keep the `.jpg` extension** and overwrite the file.

## 1. Home cards — 4 images

Shown on `/` in the "A FEW THINGS I MAKE" row. Cropped to the Editorial Card
media plate (**2.59 : 1**), so keep the subject centred.

| File | Card |
| --- | --- |
| `src/assets/home/workshop.jpg` | WORKSHOP — Software / Projects |
| `src/assets/home/build-archive.jpg` | BUILD ARCHIVE — Gunpla / Models |
| `src/assets/home/gaming-log.jpg` | GAMING LOG — PlayStation / Games |
| `src/assets/home/reading-log.jpg` | READING LOG — Books / Goodreads |

No target size: the build derives what it needs. The plate is 310 CSS px wide
at its largest — four columns inside the 1312px container — so the widths
emitted are 320 and 620, the latter being that plate on a 2x screen. **Supply
something at least 620px wide** and the rest is automatic; below that the
build would have to upscale.

Nothing is gained by supplying more than about 1000px either. These are
decorative cards in a 2.59:1 letterbox, not a lightbox.

## 1b. Brand marks

In `src/assets/`, not regenerated by `npm run placeholders`.

| File | Size | Used by |
| --- | --- | --- |
| `logo-trans.png` | 465 × 466 | The mark in both header lockups |
| `logo.png` | 465 × 466 | Nothing — same mark matted onto opaque black |
| `Shinigamae Logos.png` | 1420 × 499 | Nothing yet — wordmark banner, also matted |

Only `logo-trans.png` has a transparent background, which is why it is the one
the headers use: the matted pair draw a black rectangle wherever they sit on
the panel fill (`#18181B`) rather than the canvas. A transparent export of the
wordmark banner would be usable as a header lockup or an OG image.

The unused two are sources, not assets: nothing imports them, so nothing in
`src/` is emitted for them and they cost the deploy nothing. **Anything that
needs a fixed, guessable URL — an `og:image`, most obviously — has to move
back to `public/`,** because the imported pipeline hashes filenames.

The mark is imported at 32px (28 on mobile) with a 2x companion, so the page
fetches about 1.4KB of WebP rather than the 63KB source.

The favicon is `public/favicon.svg` — the same mark as a vector, and the one
image that still needs a fixed URL.

## 1c. Clients — 2 images each

Shown on `/workshop` under CLIENTS. Both are optional and the card degrades
without either: no shot leaves the plate showing the bare host, no logo leaves
the client's name doing the work.

| File | Size | What |
| --- | --- | --- |
| `src/assets/clients/<id>-shot.jpg` | 1680 × 1050 | Their site. 16:10, cropped from the top — a homepage screenshot reads better anchored at the masthead than centred. |
| `src/assets/clients/<id>-logo.png` | 480 × 120 | Their mark. Contained, not cropped, so the plate size is a maximum rather than a target. |

`<id>` is the entry's `id` in `src/content/clients/clients.json`, and the two
paths are written into that file as `logo` and `shot`.

**Logos want the primary on-transparent export** — whatever the brand kit
calls its default. The chip behind the logo used to be the panel fill
(`#18181B`) and so wanted the "reverse" or "on dark" variant instead; it is
now the ink (`#E4E4E7`), because the marks that actually turned up are drawn
for a white page and half of them vanished on the dark one. PNG or any format
with an alpha channel; the build re-encodes to WebP either way.

**Trim the transparent margin.** The chip sizes the logo by height, so padding
baked into the export is padding you paid for — Zespri's mark sat in a frame
half again its own size and rendered at half the height of the others.

**All eight slots are now the clients' own artwork** — BestMed, Menlo
Security, Zespri and Soctrip, shot and logo apiece. The last two placeholders
to go were the Zespri and Soctrip shots.

Dropping a pair of files and the entry's `logo` / `shot` keys stays a valid
end state rather than a broken one: the card degrades to the bare media well
with the host line doing the work.

The sizes above are maxima worth having, not minima to hit. The real shots
came in at 951 x 595, above the 840w the plate emits, so nothing upscales —
but there is no headroom if that grid ever widens.

## 2. Builds — no images to replace

The BUILD ARCHIVE is generated from the Blogspot feed by `npm run blog:sync`,
and its images come with it:

- **hero** — the YouTube thumbnail of the build's video, at `maxresdefault`.
- **photo set** — the photos in the post, hotlinked from Google's CDN and
  rewritten to `/s1600/` so the archive shows the originals rather than
  Blogger's display crops.

Nothing lives in `public/images/builds/`. To change what a build shows, change
the post: the next sync picks it up.

---

## 3. Games — nothing to replace

The GAMING LOG is generated from PlayStation Network by `npm run games:sync`,
and its art comes with it, hotlinked: the trophy-set `icon`, plus store `art`
where a played-games record matched. Every game has an image without you
doing anything.

Your own captures are optional and take precedence when present. Put them in
`public/images/games/` at **16 : 9** and attach them per game in
`src/content/games-overrides.json`:

```json
"elden-ring": { "screenshots": ["/images/games/elden-ring-01.jpg"] }
```

The **first** screenshot wins the card, the "CURRENTLY PLAYING" plate and the
detail hero, outranking PSN's art.

These go in `public/` — create the directory — because the override file
addresses them by path, and a path cannot be resized or re-encoded. Size them
yourself: 1200px wide is plenty for a card.

---

## 4. Books — no images to replace

The READING LOG is generated from Goodreads by `npm run books:sync`, and cover
art comes with it — `book_large_image_url`, hotlinked from `i.gr-assets.com`.

Nothing lives in `public/images/books/`. To change a cover, change the edition
on Goodreads: the next sync picks it up.

## Practical notes

**Everything is cropped with `object-cover`**, meaning it fills the plate and
overflows on the long axis. Centre your subject. Nothing is letterboxed.

**Local images are optimised at build time.** `EditorialCard` renders an
imported image through `<Picture>` — AVIF and WebP at 320w and 620w, with a
JPEG fallback — and the header mark through `<Image>`. Encoder quality is set
to 80 rather than the default: measured against a lanczos resize of each
source, the default lands around 30 dB PSNR, which shows on a detailed photo,
where 80 sits at 39-41 dB and is not distinguishable from the source. The four
home cards went from 530 KB of JPEG to about 136 KB of AVIF on a 2x desktop,
and 47 KB on a phone.

The generated files carry content-hashed names, so replacing a photo
invalidates its own cache and nothing else.

**Remote images are not optimised, and cannot be.** Build, game and book art
is hotlinked from Blogger, PSN and Goodreads at whatever size those services
serve. `EditorialCard` takes a plain `<img>` path for exactly that case. If
that ever needs to change, the images have to be pulled into the repo first.

**Alt text.** Builds, games and books derive alt text from the entry title.
Home card images are decorative (`alt=""`) because the card title beside them
already carries the meaning. If a home image becomes informative, give it real
alt text in `src/pages/index.astro`.
